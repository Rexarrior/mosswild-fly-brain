# Черновик для Хабра

[Habr-fly-brain.md](Habr-fly-brain.md) — рассказ об эксперименте, дополненный сенсорным режимом: основная история и одиннадцать раскрываемых технических вставок. Публикация не выполнялась.

[Habr-fly-brain.preview.html](Habr-fly-brain.preview.html) — локальный предпросмотр с изображениями и свёрнутыми вставками. Он воспроизводит чтение и раскрытие блоков, но не имитирует оформление редактора Хабра.

[Habr-editing-prompts.md](Habr-editing-prompts.md) — найденные в сети источники и адаптированные промпты для итеративной редактуры. Рабочие версии сохранены в `Saved/BrainLab/analysis/habr-editing-20260920/`.

В Markdown стоят локальные пути к пятнадцати изображениям для просмотра в Codex: семь иллюстраций и восемь схем. При переносе в редактор Хабра нужно загрузить изображения из `assets/` и заменить адреса. Основные иллюстрации:

- `mosswild-beetle.jpg` — новый крупный план настоящей модели NPC из Unreal, снят 21 сентября 2026 года. Для портрета жук перемещён на свободный участок временной приостановленной PIE-сцены, интерфейс скрыт, карта не сохранялась. Это постановочный кадр для статьи, а не снимок ночного прогона. Скрипт `capture_unreal_stills.py` воспроизводит съёмку и возвращает редактор к исходной карте.
- `mosswild-circling.gif` — реконструкция раннего петляния возле еды из журнала девятого цикла. Игровой видеозаписи этого эпизода не сохранилось. Схематичная форма жука наложена на настоящие координаты; подробности ниже.
- `mosswild-colony.jpg` — копия `Docs/Mosswild-Cyan.jpg`, кадр из предыдущей тестовой сессии; это не снимок ночного прогона.
- `mosswild-night.png` — график ночного прогона по журналу. Время на осях игровое; доставка приведена к единицам еды за игровую минуту, включая последний неполный интервал.

Восемь схем `controls-*.png` помещены внутри `<spoiler title="…">` с пустыми строками вокруг содержимого — это формат из [справки Habr Flavored Markdown](https://habr.com/ru/docs/help/markdown/). Они показывают общую границу управления, обучение декодера, прогноз положения, экономику, приоритеты задач, социальные поправки, новый сенсорный режим и выполненное сравнение с простым моторным контроллером. SVG рядом с PNG сохранены для последующего редактирования. Это поясняющие схемы по коду, не новые экспериментальные результаты; границы каждого сравнения описаны в соответствующей вставке.

Граница ответственности проверена по `Source/RPGPrototype/InsectBiome.cpp`, `InsectLab.cpp`, `InsectAgent.cpp`, `InsectBrainBridge.cpp`, `InsectSensory.cpp` и адаптерам в `Scripts/BrainLab/`. Первая схема отражает версию Mosswild с планировщиком из ночного запуска. В последующих вставках разделены десять итераций, исправление задержки, экономика и отдельный опыт с одновременными раздражителями.

Схемы и предпросмотр воспроизводятся из корня проекта:

```sh
Saved/BrainLab/venv/bin/python Docs/Articles/render_control_diagrams.py
python3 Docs/Articles/render_article_preview.py
```

Первый скрипт использует Matplotlib из окружения эксперимента. Второй — уже установленный Node.js и Marked из комплекта Codex; альтернативные пути задаются через `--node` и `--marked`. В HTML локальные адреса изображений становятся относительными, а `spoiler` — обычными закрытыми `details`. HTML можно открыть рядом с каталогом `assets/` без сервера.

## Дополнение о сенсорном режиме

Опора — коммит `21ca746`, `Docs/Sensory-controller.md` и четыре завершённых прогона `sensory-visible-v1-{sensory,planner}-{1701,2701}`. Два прерванных пилота и последующая незавершённая live-сессия в сравнение не включены. История ночного прогона сохранена отдельно: в новом сравнении у планировщика изменены контактные правила, а внешние роевые поправки отключены у обоих режимов.

- `controls-sensory.png` / `.svg` — разделение работы C++, адаптера и коннектома при одновременных раздражителях.
- `mosswild-sensory-comparison.png` — численность и накопленная доставка, суммарно по двум колониям. Цвет — режим, вид линии — начальное состояние.
- `mosswild-sensory-paths.png` — наблюдавшиеся траектории всех NPC в четырёх прогонах. Цвет — движок; строки — начальные состояния, столбцы — режимы.
- `sensory-data.json` — необходимые для графиков значения и геометрия с именами прогонов и SHA-256 исходников. Финальные снимки включены; графики не сглаживаются.

Графики воспроизводятся без Unreal и нейронной симуляции:

```sh
Saved/BrainLab/venv/bin/python Docs/Articles/render_sensory_figures.py
```

Флаг `--extract` заново собирает данные из сохранённых четырёх запусков в `Saved/BrainLab/iterations/`. Только новую схему можно обновить командой `render_control_diagrams.py --sensory-only` в том же Python-окружении. Редакторские снимки дополнения находятся в `Saved/BrainLab/analysis/habr-sensory-20260921/`.

## Контроль без коннектома

Восемь получасовых прогонов `motor-control-v1`, четыре seed, сравнивают полный нейронный мотор с формулой `reactive-v1`. В обоих вариантах снят частотный порог контактных действий и используется одинаковый синхронный шаг мира. Это отдельная серия, отличающаяся от прежнего сравнения планировщика и раздражителей. Протокол и результаты: `Docs/Controller-control.md`.

- `controls-motor-control.png` / `.svg` — одинаковый сенсорный интерфейс, два моторных блока и общие правила тела/контакта. Заменяет в статье прежний план `controls-baseline.png`; исторический файл сохранён.
- `mosswild-controller-control.png` — доставка и медианное время пакетного расчёта. Правая шкала логарифмическая; измерение сервиса исключает HTTP и рендер.
- `controller-control-data.json` — все восемь результатов, парные различия, план и SHA-256 источников. Значения включают `complete.json`.

```sh
Saved/BrainLab/venv/bin/python Docs/Articles/render_controller_control.py
```

Обычный запуск использует только компактный JSON. Для обновления из завершённой серии сначала запусти `Scripts/BrainLab/summarize_controller_control.py --prefix motor-control-v1`, затем рендер с `--extract`. Редакторские версии и проверка дополнения — `Saved/BrainLab/analysis/habr-control-20260922/`. Контактные smoke-проверки отделены от свободного поведения в основной серии.

## Предыдущие иллюстрации

Источник графика ночного прогона — сессия `20260919-172604-EE71FCF0D64793ED76C71E8724002C6E`. В `assets/mosswild-night-data.json` сохранены получасовые суммы доставки и выборка численности: каждые 30 игровых секунд, обе стороны каждого изменения численности и конечная точка. Значения не сглаживаются.

График воспроизводится из корня проекта:

```sh
MPLCONFIGDIR=Saved/BrainLab/mpl-cache Saved/BrainLab/venv/bin/python Docs/Articles/render_habr_chart.py
```

GIF использует 52 отсчёта SiliconFly №2 из `Saved/BrainLab/iterations/09-readout/trace.jsonl`, от 455.162 до 516.347 секунды мира. Шаг записи — около 1.20 секунды. Между отсчётами линейно интерполируются позиция и энергия, направление интерполируется по кратчайшей угловой дуге. Ноги схематичные и не анимированы; их движения журнал не сохранял. Сам момент смерти не реконструируется. Ускорение ×5, задержки кадров округлены до 10 мс; длительность GIF — 12.32 секунды с короткой задержкой последнего кадра.

Фрагмент исходных данных и SHA-256 журналов находятся в `assets/circling-data.json`. GIF воспроизводится без Unreal и без запуска нейронных моделей:

```sh
Saved/BrainLab/venv/bin/python Docs/Articles/render_circling.py
```

Крупный план снимается при открытом редакторе RPGPrototype и остановленной игре:

```sh
python3 Scripts/ue.py script Docs/Articles/capture_unreal_stills.py
```

Скрипт отказывается запускаться при несохранённой карте или существующем `mosswild-beetle.jpg`: текущий портрет сначала нужно отдельно сохранить. Результат и сведения о временной съёмке записываются в `Saved/BrainLab/analysis/habr-editing-20260921/capture.json`.
